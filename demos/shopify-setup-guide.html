术语速查 · 看不懂的词先点这里
落地页 (Landing Page)
为一个广告 / 一个人群单独做的独立页面，进来的人只看到一件事、一个下单按钮，不被首页的杂七杂八分心。
Page（页面）
Shopify 里的一种内容页，用来放「关于我们 / FAQ / 落地页」这类不是商品也不是博客的内容。后台在「在线商店 → 页面」。
handle（网址后缀）
一个页面 / 商品网址最后那一段。比如 aroundfire.co/pages/propane-fire-pit-table 里加粗那段就是 handle，可自己指定，直接影响 SEO。
variant（变体 / 规格）
同一个商品下的不同规格。比如 Gather Lite 有「木柴版 / 燃气版」，燃气版就是一个 variant。每个 variant 有一串数字 ID，加购按钮要接的就是这串 ID。
variant ID
某个规格的唯一数字编号（一长串数字）。加购链接 /cart/variant_id:1 里填的就是它。下面第 4 步教你怎么找。
Custom Liquid（自定义 Liquid 区块）
Shopify 主题编辑器里的一个「万能积木」，能直接塞进一整段 HTML / CSS 代码。我们用它把设计稿贴进去，不用装插件、不用改主题源码。
模板 (template)
决定一个页面长什么骨架。给落地页单独指定一个「空白模板」，它就不会带上普通页面的边距和标题。
SEO
搜索引擎优化。让 Google 更容易找到并展示你的页面。
title / meta description
你的页面在 Google 搜索结果里显示的标题和那句灰色描述。Shopify 页面底部可以直接填。
canonical（规范网址）
告诉 Google「这个内容的官方正版网址是哪个」，防止多个相似网址被判成重复内容、互相抢排名。
Merchant Center / Feed
Google 购物的商品库。你的商品信息（图 / 价 / 标题）传上去，才能出现在搜索页顶部那排带图的购物位。
KD（关键词难度）
Keyword Difficulty，0–100。数字越低越好抢排名。本文里 KD≤15 都算「好打」。
CPC（单次点击成本）
Cost Per Click。投搜索广告时，别人点你一下大概花多少钱（美元）。
Volume（月搜索量）
这个词在美国每月被搜多少次。
ROAS
广告花 1 块换回几块销售额。3 以上算健康，你账户整体 5.69 很好。
否定词 (Negative Keyword)
告诉 Google「有这个词的搜索别给我展示广告」，用来挡掉不相关、白花钱的点击。
DSA（动态搜索广告）
不用你预先填词，Google 自动根据你落地页内容去匹配相关搜索。适合「知道有需求、但手上没有现成关键词」的场景——正好是这个燃气页的处境。
广泛匹配 / 搜索词报告
广泛匹配＝让一个词去覆盖它的各种说法；搜索词报告＝后台能看到「用户到底搜了什么词触发了你广告」，用来反向挖出真实关键词。

一在 Shopify 后台把这个页面建出来

先定用哪种方式建，再一步步搭。下面所有「点哪里」都按当前 Shopify 后台的通用结构写；不同主题 / 插件版本菜单名可能略有差别，遇到对不上的以你自己后台实际界面为准。

0. 先选建页方式（这步决定后面怎么做）

你手上是一份已经写好的整页 HTML 设计稿，不是要从零拖拽。基于这个前提，三种方式的取舍：

✅ 推荐

方式 A：独立 Page + 自定义 Liquid 区块

新建一个 Page，给它指定一个几乎空白的模板，在主题编辑器里加一个「Custom Liquid」区块，把设计稿 HTML 整段贴进去。

为什么推荐：零月费、不装插件、不改主题核心文件、独立网址 + 独立 SEO 完全可控；设计稿已是成品，贴进去即用。缺点是图片要手动传上去换链接、加购按钮要手填 variant——但都是一次性的。

备选

方式 B：落地页插件（PageFly / Shogun）

装一个落地页 App，用可视化拖拽搭，商品块能直接绑定真实 variant、自带吸底加购。

什么时候才选它：你以后要频繁自己改版、且不想碰任何代码。代价是每月订阅费 + 学习这个 App。已有现成 HTML 的情况下它并不省事，反而要重搭。

不推荐

方式 C：直接用产品页

把燃气版做成某个产品页去打广告。

为什么不推荐：产品页被产品模板框死，很难放这套「禁火令痛点 + 合规 FAQ + 痛点叙事」的自由排版，网址也带 /products/ 前缀不利于独立 SEO 叙事。这个页的价值就在「独立叙事」，用产品页等于废掉一半。

下面的步骤按「方式 A」写。如果你已经装了 PageFly / Shogun 且更习惯它，可跳过第 3 步的贴代码部分，改成在 App 里粘贴 / 重搭，但第 1 步（网址）、第 4 步（加购接 variant）、第 6 步（SEO）、第 7 步（吸底条）的逻辑完全通用。

  1. 新建一个 Page，把网址后缀设成 propane-fire-pit-table

    后台左侧 在线商店 Online Store → 页面 Pages → 添加页面 Add page

    标题（Title）先随便填个内部名，比如 Propane Fire Pit Table LP（这个标题只在后台看，不是给客户看的 SEO 标题，那个在第 6 步单独设）。

    关键在页面底部的 Search engine listing（搜索引擎预览） 区，点 Edit / 编辑，把 URL handle 改成：

    propane-fire-pit-table

    最终网址就是 https://www.aroundfire.co/pages/propane-fire-pit-table——这正是关键词意图和广告要指向的独立 URL。

    📷 截图位Pages 列表页 + 新建页面时底部「Search engine listing → URL handle」输入框（上线时请你自己在后台截图存档，本文档不放假截图）。
  2. 给这个页面单独指定一个「空白 / 落地页」模板

    还在这个页面的编辑界面，右侧栏找到 Theme template（主题模板） 下拉框。默认是 page（会带上普通页面的标题栏和左右留白，不适合整页设计稿）。

    选一个更干净的模板。多数主题自带 page.contact 之类；最理想是新建一个专用模板：在线商店 → 主题 Themes → 自定义 Customize → 顶部页面选择器切到这个 Page → 左上「Create template / 创建模板」→ 命名 propane-lp，把里面除了「Custom Liquid」以外的默认区块（页面标题、正文）都删掉或隐藏。

    回到页面编辑，Theme template 选 page.propane-lp。这样这个页面就是一张干净画布，不会顶着一个多余的大标题。

  3. 把设计稿 HTML 贴进 Custom Liquid 区块（核心一步）

    主题 → 自定义 → 切到 propane-lp 模板 → 添加区块 Add section / Add block → 选 Custom Liquid（自定义 Liquid）

    把 gas_landing_page.html 里 <body> 和 </body> 之间的所有内容，连同 <head> 里那段 <style>...</style> 一起，粘贴进 Custom Liquid 框里。（把 <style> 也一并贴进去，页面样式才不会丢。）

    三个上线前必须处理的地方：

    • 删掉顶部的 DEMO 标识条：设计稿里那句「● DEMO · 方案设计稿 ●」是给你看的，别让客户看到，整行 <div class="demobar">...</div> 删掉。
    • 图片链接要换成真图：设计稿里写的是 assets/gather_family.jpg 这种本地路径，上线后打不开。先把要用的图上传：内容 Content → 文件 Files → 上传，上传后每张图会得到一个 https://cdn.shopify.com/... 的 CDN 网址，把 HTML 里对应的 assets/xxx.jpg 逐个替换成这些真网址。（背景图是写在 <style> 里的 url('assets/...')，别漏了。）
    • 顶栏 / 页脚可能和主题重复：如果你的主题本身已经有网站导航和页脚，设计稿里自带的 .topbar 顶栏可以删掉，避免出现两条导航。页脚的合规声明那段 务必保留（合规红线，见文末）。
    📷 截图位主题编辑器里「添加区块 → Custom Liquid」的位置，以及粘贴后的实时预览。上线时自行截图。
  4. 把「Add to Cart」接到真实的燃气版 variant（$259 / $349）

    设计稿里的加购按钮现在是 href="#" onclick="return false;"（假的，点了不动）。要让它真能下单，得接到燃气版那个规格的 variant ID。

    先确认燃气版规格存在。调研发现：燃气能力目前是以一个 $33 的 Camping Stove 配件形式埋在配件区的，并没有一个独立命名、独立定价 $259/$349 的「燃气版」规格。所以第一件事是在商品后台把燃气版作为一个 variant（或独立商品）建出来并定价 $259 / $349：产品 Products → 打开 Gather Lite / Grande → Variants（变体）→ 新增一个 option（如 Fuel = Propane）→ 设价 $259 / $349。这一步涉及你真实的产品与库存结构，以你后台实际为准。

    再拿到这个 variant 的 ID：两种办法任选——

    • 后台法：进到那个 variant 的编辑页，浏览器地址栏里会有 .../variants/1234567890 这一长串数字，就是它。
    • 前台法：浏览器打开 https://www.aroundfire.co/products/{商品handle}.js，页面里每个 variant 都列了 "id": 1234567890，找到燃气版那条。

    把按钮改成加购链接。最省事的做法是用 Shopify 自带的购物车永久链接，把设计稿里两处（Lite / Grande）和吸底条里的按钮 href 改成：

    /cart/{变体ID}:1 （加一件直接进购物车）

    想点了直接跳结账，用 /cart/{变体ID}:1?checkout。同时把 onclick="return false;" 删掉。Lite 按钮填 Lite 的 ID，Grande 按钮填 Grande 的 ID，吸底条那个下拉可先简单指向 Lite。

    别用假 ID，也别乱猜。variant ID 必须从你自己后台 / 前台取到真实值。取不到就先别上线加购，宁可按钮暂时指向现有产品页，也不要接一个会报错的链接。
  5. 让评价（Reviews）在这个页面显示出来

    设计稿里放了「4.91★ / 104 reviews」这种数字，但那是写死的展示占位，上线要接你真实在用的评价 App（如 Judge.me / Loox / Okendo——以你店铺实际装的为准）。两种做法：

    • 先共用主产品评价（推荐起步）：燃气版和木柴版是同一张桌子平台，初期没有单独的燃气版评价很正常。可以先在页面里嵌入 Gather Lite / Grande 主产品的评价小组件——多数评价 App 提供一段可粘贴的代码 / Liquid 片段（在 App 后台找 "Embed / Widget code"），或用它的「按 product ID 显示评价」功能，填主产品的 ID。
    • 以后再拆出燃气版专属评价：等燃气版有了自己的订单和评价，再在 App 里按燃气版 variant / product 单独调取。

    上线前把写死的数字对齐真实值：设计稿里那句「confirm exact figures at publish（上线时核对真实数字）」就是提醒你——4.91 / 104 / 541 backers / $134,789 这些要么接 App 动态显示，要么手动改成当下真实数字，不能挂一个和后台对不上的数。

  6. 填 SEO：title / meta description / canonical

    回到 在线商店 → 页面 → 这个页面 → 底部 Search engine listing → 编辑，填两栏：

    字段填什么（可直接抄设计稿里已写好的）
    Page titlePropane Fire Pit Table — Grill & Gather Even During a Fire Ban | AroundFire
    Meta descriptionAroundFire's propane fire pit table lets you grill and gather when wood fires are banned. Portable, shut-off-valve propane — permitted under many Stage 1 & Stage 2 fire restrictions. From $259.

    canonical（规范网址）：Shopify 给每个页面会自动生成一个正确的 canonical 指向自己，正常情况你不用手动填。只有一种情况要留意——如果你为了投不同广告，复制出好几个内容几乎一样的落地页，那要把这些副本的 canonical 都指向这一个主版本，避免 Google 判重复。手动改需要在主题的 theme.liquid 或页面模板里加一行 <link rel="canonical">，这属于改主题代码，没把握就先别动，保持 Shopify 默认即可。

    注意：设计稿的 <head> 里有 noindex,nofollow（不让 Google 收录），那是因为它是「设计稿」。真上线这个页面时，不要把 noindex 带上去——Shopify 页面默认就是允许收录的，你只要别去主题里手动加 noindex 就行。

  7. 移动端吸底加购条（Sticky Add to Cart）

    好消息：设计稿里已经写好了吸底加购条（就是手机上滚动时始终贴在屏幕底部的那条 "From $259 / Add to Cart"）——它是纯 HTML+CSS，随第 3 步贴进 Custom Liquid 时就一起带进来了，只要在第 4 步把它的按钮 href 也接上真实 variant 即可，不需要额外装插件。

    只有两种情况需要用插件的吸底条来替代：① 你的主题本身已经有一个吸底条、和设计稿这条打架；② 你想让下拉框在 Lite / Grande 之间切换时按钮 ID 也跟着变（这需要一点 JS，或者干脆用支持 sticky ATC 的落地页 App / 主题原生功能）。否则设计稿自带的这条已经够用。

  8. 上线前，补齐所有 [to be confirmed] 真实规格 ⚠️
    这一步不做完不能上线 规格表里这些字段现在是占位符，必须换成你产品的真实数据，一个都不能留着 [to be confirmed] 发布：
    • 展开尺寸 / 折叠尺寸（L×W×H）
    • 重量（Lite / Grande 各自）
    • BTU 火力输出
    • 认证（如有 CSA/UL 等——注意：认证不等于禁火令期间就合法，见文末合规红线，认证只写事实、不作合规承诺）
    这些数字我无法替你填，编一个假的比留空更糟。填之前这个页面只是设计稿，不是可上线页面。

二广告怎么配（Google + Meta）

先讲一个必须诚实说清的数据事实 这个落地页打的是「propane / fire ban / burn ban（丙烷 / 禁火令）」搜索意图。但你提供的关键词表（谷歌 sheet，218 个带 Volume/KD/CPC 的有效词）里，propane、fire ban、burn ban、gas、smokeless 这些词一个都没有（0 命中）。也就是说，落地页最核心的那层意图，关键词表里没有可用来出价的真实数据。这不是我漏筛，是原表就没采这批词。

所以下面 Google 部分拆成两半：① 能用真实数据打的词（表里确实有量、且贴产品的 fire pit + grill / 便携 / 烤网词，全部给真实 Volume/KD/CPC）；② propane/禁火令这层意图——关键词表无数据，我不编数字，改用「动态搜索广告 + 广泛匹配探词」的打法，靠搜索词报告反挖真实词。趋势侧的旁证（如 portable fire pit amazon 12 个月 +110%、smokeless fire pit 5 年 +900%）来自 market_trends 报告的 Google Trends 实测，但那是趋势指数、没有 Volume/KD/CPC，只能当方向信号，不能当出价依据。
