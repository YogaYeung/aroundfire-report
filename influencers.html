一处理方法

URL 归一化

  • 剥离追踪参数：fbclid、_t、_r、shop_region、igsh、utm_*、is_from_webapp、si、feature 等
  • 剥离锚点与尾部斜杠
  • 平台识别：instagram.com/xxx → IG:xxx；tiktok.com/@xxx → TT:xxx；youtube.com/@xxx·/c/·/user/·/channel/ → YT:xxx
  • 排除非主页路径（/p/、/reel/、/explore/、/video/）

解析失败 2 条（占 674 的 0.3%）：两条是帖子链接不是主页链接，无法反推达人 handle，已剔除并单独记录。

跨表去重（并查集 Union-Find）

每条记录生成两类键：强键 平台:handle（精确匹配）；弱键 ~handle（跨平台同名）。

弱键是必要的——台账里一个人常常只填了 TikTok 链接，而 ID 字段就是他的 IG handle；不用弱键就会漏合并。弱键的误合风险在本数据集里可接受（这批 handle 都足够独特，未发现同名不同人的情况）。

  1. 拆字段：「状态」拆成「触达渠道」+「当前进度」+「触达日期」三列，否则永远算不出渠道回复率
  2. 补画像：658 个只有链接的达人必须做一次批量 enrichment（粉丝数、互动率、受众年龄性别、邮箱）。没有粉丝数和受众画像，第七节的优先级排序只能靠 handle 关键词粗筛，精度有限——这是本次分析最大的方法论局限，必须诚实标注
  3. 加标签：按「主理人性别/年龄段」「是否有孩子」「场景（后院/营地/车/RV）」「是否真人出镜口播」四个维度打标，直接对应 Meta 端可验证的人群与素材特征
  4. 建搜索-外联的强制流转：搜索库每周固定往外联队列推 N 人，避免再出现「搜了 674 个、只联系了 2 个」
方法论局限（诚实声明）：达人性别/年龄类判断在无画像数据时仅基于 handle 关键词与台账中文备注推断，已在文中逐处标注。总库 695 人中 94.7% 只有一条链接，因此第七节 P1 的三类画像只能给出「筛选方向 + 库存量」，不能给出具体人名清单。
